Part 1 — Version (Release)

Odoo releases a new version every year with new features, better UI and bug fixes

What is a Version?
  • Odoo has many versions — one released every year
  • New version = new features, better UI, better performance, bug fixes
  • You can use any version — Odoo 17, 18, 19, 20 etc.
  • Odoo 20 is the latest version (2026)
  • Older versions still work but won't get new features
⚠️
Important: Once a company starts on a version (e.g. Odoo 17), upgrading to a newer version (e.g. Odoo 20) requires a migration process — it is not automatic.
💼
Trainer Note: When a client asks "Which Odoo version should we use?" → "Odoo 20 is the latest (2026). But any version can be used — the version just means the release year. Choose based on support lifecycle and available budget."

Odoo 20 — What Consultants & Developers Should Know

Changes visible in the Odoo 20.0 release — worth knowing before your first project

📦 Product types: Goods · Service · Combo
  • Goods replaces "Storable / Consumable" — stock is tracked with the Track Inventory checkbox
  • Combo bundles products (restaurant menus, kits sold as one line)
  • Service products still drive Tasks, Projects and Timesheets
📊 Inventory valuation: Periodic · Perpetual
  • Odoo 20 labels: Periodic (at closing) and Perpetual (at invoicing) — older versions said Manual / Automated
  • Costing methods: Standard · Average (AVCO) · FIFO — set per product category
  • Valuation data is stored in product.value records
🔐 Access rights: ir.access
  • Odoo 20 uses the ir.access model — security files are named ir.access.csv (older: ir.model.access.csv)
  • Columns: model_id, group_id/id, operation (crud, r, cru …) and an optional domain
  • Custom modules from older versions need this change to install
🧩 What stays the same
  • Version → Edition → Hosting: the three-part model still applies
  • Community is free on-premise; Enterprise adds Studio, Sign, Helpdesk, advanced accounting
  • Workflows in this deck (CRM → Sales → Inventory → Invoice) are unchanged
💡
Trainer note: Always ask which version the client runs — screens, field names and valuation labels differ between releases, so confirm before you demo or configure.

Part 3 — Hosting (Deployment)

Where is Odoo running? — Odoo can be used in 3 ways

A. On-Premise
Self Hosted — Full Control
🖥️
  • You install Odoo on your own system (laptop, VPS, AWS, company server)
  • You have full control over everything
  • Unlimited customization allowed
  • You handle backup, security & updates yourself
💰 Cost
Community → Free (only server cost)
Enterprise → License fee + server cost
Example: You install Odoo 20 Community on your laptop and run on localhost:8069
B. Odoo Online (SaaS)
Cloud — No Installation
🌐
  • Odoo runs on Odoo's servers
  • You only use it in the browser
  • No installation required
  • No custom Python modules allowed
  • Odoo manages updates automatically
💰 Cost
Only Enterprise (Paid subscription)
Per user, per month/year. No full free version.
Example: You login at company.odoo.com in your browser — this is Odoo Online (SaaS)
C. Odoo.sh (Cloud Platform)
Developer Cloud — Custom Modules
⚙️
  • Odoo's own cloud platform
  • You can install custom modules
  • GitHub based deployment
  • Odoo manages the server
  • Testing (Staging) + Production environments
💰 Cost
Only Enterprise (Paid)
Enterprise license + Odoo.sh subscription. No free option.
Flow: Developer Code → GitHub → Odoo.sh → Testing → Production

Why Accounting Exists

The financial language every business speaks

FOUR KEY QUESTIONS ACCOUNTING ANSWERS
  • How much money do we have? — Checking bank & cash balances
  • How much do others owe us? — Receivables from customers
  • How much do we owe others? — Payables to vendors/suppliers
  • Are we profitable? — Income minus expenses = net profit (Profit & Loss)
FIVE ACCOUNTING ELEMENTS
  • Assets — What the business owns (cash, stock, equipment)
  • Liabilities — What the business owes (loans, bills to pay)
  • Equity — Owner's stake (Assets − Liabilities)
  • Income / Revenue — Money earned from sales or services
  • Expenses — Money spent to run the business
The accounting equation: Assets = Liabilities + Equity
Every transaction in Odoo maintains this balance automatically.

Odoo Accounting Objects Explained

The six core objects you will work with every day in Odoo Accounting

📊
Account
A ledger bucket that collects related transactions. Example: "101000 Bank", "400000 Sales Revenue". Every transaction hits at least two accounts (Dr & Cr).
📔
Journal
Groups related entries. Odoo creates default journals: Sales, Purchase, Bank, Cash, Miscellaneous. Each invoice posts to its journal.
📝
Journal Entry
The actual accounting record — a set of Dr/Cr lines that always balance to zero. Created automatically when you post an invoice, bill, or payment.
🧾
Invoice (Customer)
Bill you send to a customer for goods/services delivered. When posted: Dr Accounts Receivable, Cr Sales Revenue.
📄
Vendor Bill
Bill received from a supplier. When posted: Dr Expense/Stock, Cr Accounts Payable. Matches the Purchase Order.
💳
Payment
Records money received (customer) or sent (vendor). Reconciles against the open invoice/bill. Dr Bank, Cr AR (received) or Dr AP, Cr Bank (paid).

Inventory & Accounting — How They Connect

Every stock movement has an accounting impact — understanding this prevents costly mistakes

When You Purchase (Buy from Vendor)
Stock Receipt Validated
Goods arrive and are accepted into the warehouse. Stock quantity and value increase.
↓
Entry when the Vendor Bill is posted (Perpetual)
Dr Stock Valuation (Asset) ↑
Cr Accounts Payable (Liability) ↑
Perpetual (at invoicing) creates the entry when the bill is posted. With Periodic (at closing), entries are suggested from the Inventory Valuation report.
When You Sell (Deliver to Customer)
Delivery Validated
Goods leave the warehouse. Stock quantity and value decrease.
↓
Entry when the Customer Invoice is posted (Perpetual)
Dr Cost of Revenue / COGS (Expense) ↑
Cr Stock Valuation (Asset) ↓
The cost becomes an expense at invoicing — revenue and cost land in the same period (the Anglo-Saxon matching principle).
💡
This only works with Goods that have "Track Inventory" enabled and Perpetual valuation (Standard, AVCO or FIFO). Services and untracked goods carry no inventory value. Always check the category valuation and costing method when setting up a client.

Anglo-Saxon vs Continental Accounting

Two accounting traditions — they decide when a purchase becomes an expense

ANGLO-SAXON — matching & perpetual
Used in: UK · USA · Canada · Australia · New Zealand · Hong Kong
  • Goal: a "true and fair view" for investors — principle-based
  • Stock stays an asset until sold, then becomes COGS (matching principle)
  • Perpetual inventory: Stock Valuation and COGS accounts move with every sale
  • Income statement by function — COGS, Selling, Admin
  • Flexible, company-defined chart of accounts
Example: buy 10, sell 4 → COGS for the 4 sold is booked with the sale; 6 remain as an asset.
CONTINENTAL — prudence & periodic
Used in: Germany · France · Spain · Italy · Belgium · many Latin American countries
  • Goal: prudence and tax / legal compliance — rule-based
  • Purchases are booked as an expense immediately (Purchases account)
  • Periodic: period-end stock count creates an adjustment (change in stock)
  • Income statement by nature — materials, wages, depreciation
  • State-prescribed charts: PCG (France), SKR03 / SKR04 (Germany)
Example: buy 10 → all 10 expensed at once; the period-end count credits back the 6 unsold units.
⚙️
In Odoo 20: it is one company flag, Use anglo-saxon accounting, set by the chart-of-accounts template (the USA, UK, Canada, Australia and New Zealand templates turn it on; the German, French, Spanish and Italian ones leave it off) — plus the valuation mode Periodic (at closing) or Perpetual (at invoicing).

Continental / Periodic

Cr Accounts Payable1,000
2. Customer invoice posted
Dr Accounts Receivable600
Cr Revenue600
3. Period end — count shows 6 units ($600)
Dr Inventory (Asset)600
Cr Change in Stock (Expense)600

1. Vendor bill posted
Dr Stock Valuation (Asset)1,000

Dr Accounts Receivable600
Cr Revenue600
3. Same invoice — cost of the 4 units

Which Standard Does Odoo Follow?

Odoo has no "IFRS" or "US GAAP" switch — the result comes from five configuration choices

1 Localization / chart of accounts
l10n_us, l10n_uk, Generic … sets account structure, taxes and statutory reports
2 Anglo-Saxon flag
Company setting Use anglo-saxon accounting — driven by the chart template
3 Inventory valuation
Periodic (at closing) or Perpetual (at invoicing) — company default and per product category
4 Costing method
Standard · Average (AVCO) · FIFO. Odoo has no LIFO — fits IFRS; a US GAAP company on LIFO needs adjustments outside standard costing

Fiscal year, lock dates and the financial reports used for statutory filing (financial statements: Enterprise)
Consultant checklist
  • Which framework do the statutory books follow — local GAAP, IFRS or US GAAP?
  • Need two sets of books (e.g. local + group IFRS)? Plan it up front: Odoo 20 Multi-Ledger groups report on a subset of journals — post IFRS adjustments in dedicated journals, or use a second company
  • Choose a costing method the framework allows
  • Decide Periodic vs Perpetual before the first stock move — changing later is a migration exercise
  • Test a full cycle: Buy → Receive → Bill → Sell → Invoice → check every entry
